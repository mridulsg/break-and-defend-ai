## Start

```bash
./shared/scripts/console-up.sh labs/c1-llm/ch05-data-and-model-attacks/data-lab/compose.yaml
```

Open <http://127.0.0.1:8300>. Two containers run: `bdai-console` (on the internal lab network) and `bdai-console-edge` (publishes `127.0.0.1:8300`). `./shared/scripts/down.sh c1` removes both, and the data volume.

## Files

```
app/trailbot.py       TrailBot: retrieval, then the model answers (read it: nothing checks where a document came from)
app/moderator.py      the review moderator: logistic regression on the words of a review, plain Python
app/autocomplete.py   the reply autocomplete: a trigram model trained on past support chats, plain Python
app/progress.py       mission progress and the flag
app/console.py        the web console backend
data/reviews.csv      300 made-up reviews: 240 for training, 60 held out for testing
data/support_chats.txt   226 made-up support chats, six of them with private details
corpus/ inbox/ web/   TrailBot's knowledge base (the same as Labs 3 and 4)
```

Every person, phone number, email, address and card number is invented. The datasets are generated by `tests/fixtures/ch05_make_data.py`.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `network bdai-llm declared as external` | The gateway is not running. Start it: `./shared/scripts/start.sh` |
| Console says "TrailBot could not get an answer from the model" | The gateway or the local model server is down (or WSL's address for Windows changed after a reboot). Start Ollama, then `./shared/scripts/start.sh`. The moderator and autocomplete pages do not need the model. |
| Browser shows "No lab console is running" | Start it with the command above. |
| The note does not change TrailBot's answer | Model output is sampled and wording matters. Open Sources used to check your note was read, and try again or reword it. |
