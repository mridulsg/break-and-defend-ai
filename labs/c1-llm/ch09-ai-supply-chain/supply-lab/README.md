## Start

```bash
./shared/scripts/console-up.sh labs/c1-llm/ch09-ai-supply-chain/supply-lab/compose.yaml
```

Open <http://127.0.0.1:8300>. Two containers run: `bdai-console` (on the internal lab network) and `bdai-console-edge` (publishes `127.0.0.1:8300`). `./shared/scripts/down.sh c1` removes both, and the data volume.

## Files

```
models/sentiment-v1.pkl          Acme's own model, as a pickle. It imports nothing.
models/sentiment-community.pkl   a "community" model. It also tells the loader to import posix.mkdir and call it.
models/sentiment-v1.json         the same weights as plain data, which cannot contain code.
data/acme-sentiment-deps.txt     a package list with the usual mistakes in it (on purpose)
data/approved.txt                the package names Acme has approved
app/reader.py                    prints a pickle's steps without running them (Python's pickletools)
app/loader.py                    the risky loader (pickle.loads) and the safe one
app/audit.py                     the dependency audit
app/progress.py                  mission progress and the flag
app/console.py                   the web console backend
```

The sample files are generated by `tests/fixtures/ch09_make_models.py`, and a unit test checks the checked-in files match its output.

## Is this safe to run?

The "dangerous" model does one thing: it makes an empty folder in `/tmp` inside the lab container, then the console removes it. It has no network, a read-only filesystem and no extra privileges. The risky loader only ever opens the three sample files by name. Nothing here is malware, but the mechanism is the same one real malicious models use, so never run this against a file you downloaded. Only read those, or scan them (Lab 9.3).

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `network bdai-llm declared as external` | The gateway is not running. Start it: `./shared/scripts/start.sh` (the lab itself does not use it, but the console's network does) |
| Browser shows "No lab console is running" | Start it with the command above. |
| A mission does not tick | Each tick needs the exact action: read the steps of **both** pickle files, load the **community** file, and so on. The Missions page shows what is missing. |
